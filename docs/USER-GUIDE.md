# Инструкция по работе с LogisticsWeb

Пошаговое руководство для пользователя приложения: как запустить, добавить клиентов, построить маршрут и прочитать результат.

## 1. Запуск

**Что нужно:** .NET 8 SDK и интернет (для карты и дорожных расстояний).

```bash
dotnet run
```

Приложение поднимается на **http://localhost:5085**. Откроется страница «Маршрут».

Если порт занят или нужен HTTPS:

```bash
dotnet run --urls http://localhost:5090
dotnet run --launch-profile https     # https://localhost:7237
```

Остановить — `Ctrl+C` в консоли.

## 2. Две вкладки приложения

| Вкладка | Для чего |
|---|---|
| **Маршрут** | Карта, генерация точек, расчёт и финансовая таблица |
| **Клиенты** | База клиентов: добавление, правка, удаление, импорт на карту |

Данные клиентов хранятся в `App_Data/clients.json` и сохраняются между запусками. Набор точек на карте живёт в сессии: сбрасывается при перезапуске сервера или через 30 минут простоя.

## 3. Добавление клиента

1. Откройте вкладку **Клиенты**.
2. В блоке «Добавить клиента» заполните:
   - **ФИО клиента** — произвольный текст;
   - **Адрес** — начните вводить (минимум 3 символа), появится список подсказок из справочника адресов Москвы; **выберите строку из списка**, чтобы подставились координаты;
   - **Сумма заказа, ₽** — доход, который приносит этот заказ.
3. Нажмите **Добавить**.

> Важно: если адрес не выбран из подсказок, координаты не сохранятся, и точка не попадёт на карту при импорте. Всегда кликайте по строке в выпадающем списке.

Адрес, введённый вручную и точно совпадающий со справочником, тоже распознаётся — координаты подставятся на сервере.

## 4. Работа со списком клиентов

Таблица внизу страницы:

- **Сохранить** — применяет изменения в строке (ФИО, адрес, сумма). Координаты при правке не пересчитываются автоматически: чтобы обновить адрес и координаты, удалите клиента и добавьте заново.
- **Удалить** — удаляет клиента из базы сразу, без подтверждения.

Счётчик в заголовке («Список клиентов (N)») показывает текущее число записей.

## 5. Построение маршрута

На вкладке **Маршрут** три кнопки — ими пользуются по порядку:

| Кнопка | Что делает |
|---|---|
| **1. Сгенерировать случайные точки** | Демо-режим: 5–7 реальных адресов Москвы со случайными заказами (1 000–35 000 ₽). Ничего вводить не нужно |
| **2. Рассчитать оптимальный маршрут** | Строит матрицу дорожных расстояний и ищет самую прибыльную комбинацию остановок. Кнопка активна, только когда точки есть |
| **3. Импорт клиентов из базы** | Берёт клиентов с координатами из базы и ставит их точками на карту |

Склад (старт и финиш) добавляется автоматически: базовая точка 55.751244; 37.618423.

**Сколько ждать:** расчёт обращается к публичному OSRM для каждой пары точек. Для 5–7 точек это обычно 5–20 секунд. Если сервис недоступен, используются расстояния по прямой с коэффициентом 1.25, и расчёт проходит быстрее.

## 6. Как читать результат

**На карте:**

| Цвет маркера | Значение |
|---|---|
| Синий | Склад (старт и возврат) |
| Зелёный | Клиент включён в маршрут; в подсказке указан номер остановки |
| Красный | Клиент отброшен: поездка к нему не окупает дорогу |
| Серый | Точка не участвовала в расчёте (ещё не считали) |

Зелёная линия со стрелками — фактический трек по дорогам, полученный из OSRM.

**Карточка «Финансовые показатели»:** общий доход, пробег, расходы и чистая прибыль.

**Таблица «Детализация затрат по этапам»:** для каждого этапа — расстояние участка, доход заказа, затраты на дорогу (900 ₽/км) и прибыль участка; в последней строке — итог по маршруту.

Формула, по которой всё считается:

```
прибыль = сумма заказов − пробег (км) × 900 ₽
```

Если итоговая прибыль отрицательная, маршрут в текущем виде убыточен: стоит поднять стоимость доставки, снизить цену километра или убрать дальние дешёвые заказы.

## 7. Типичные ситуации

| Симптом | Причина и решение |
|---|---|
| Карта серая, без улиц | Нет доступа к `tile.openstreetmap.org`. Проверьте интернет или блокировщик |
| Кнопка «Рассчитать» неактивна | На карте нет точек: сначала сгенерируйте их или импортируйте клиентов |
| Клиент есть в базе, но не на карте | У него не заданы координаты — адрес не был выбран из подсказок. Удалите и добавьте заново через автодополнение |
| Расчёт идёт долго | Публичный OSRM перегружен. Подождите или уменьшите число точек |
| Маршрут пропал после перезапуска | Точки хранятся в сессии. Нажмите «Импорт клиентов из базы» или сгенерируйте точки заново |
| Все точки красные | Заказы слишком малы относительно расстояний. Увеличьте суммы заказов или уменьшите стоимость километра (`CostPerKm` в `Pages/Index.cshtml.cs`) |

## 8. Ограничения

- Расчёт — полный перебор: комфортно до ~10 точек, дальше время растёт факториально.
- Нет авторизации и разделения пользователей: приложение рассчитано на локальный запуск одним человеком.
- Стоимость километра (900 ₽) задана в коде константой, а не в интерфейсе.
- Изменение адреса в таблице не пересчитывает координаты — только добавление через автодополнение.
